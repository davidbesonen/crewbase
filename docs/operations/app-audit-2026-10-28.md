# KnowShow application audit — October 28, 2026

## Scope

Reviewed the main company and crew journeys, profile and company pages, tour/show
staffing, job posting, availability, roster imports/claims, invitations, offers,
analytics destinations, administrator access, light/dark appearance, and mobile
layouts. Validation includes the Rails regression suite, browser system suite,
RuboCop, architecture boundaries, and Brakeman. This is a code and functional
audit, not a certification or a test of real payment/email delivery.

Release verification: 975 Rails tests (7,684 assertions) and 39 browser scenarios
(1,091 assertions) passed; RuboCop checked 787 files without offenses, Zeitwerk
passed, and Brakeman reported no scan errors with the five reviewed warnings
described below.

## Corrections

- Profile and company web links now accept only HTTP/HTTPS destinations without
  embedded credentials. Bare domains become HTTPS links. Unsafe legacy values
  are omitted at render time; stored profile details are preserved.
- External calendar downloads enforce a 2 MB limit using both declared size and
  download progress, then check size again before parsing. Imports reject event spans over 3,660 days and
  totals over 10,000 blockout days before writing any availability changes.
- Cancelled events and events explicitly marked free/transparent no longer block
  availability. Failed imports keep the last successful calendar snapshot.
- Startup skips venue writes when the bundled catalog's checksum and stored row
  count match the last successful import. Changed catalogs, missing records, or
  an evicted cache trigger a transactionally complete refresh. Operators can use
  `FORCE=true bin/rails venues:import` to refresh deliberately. The first startup
  after this deployment still imports once to establish the checksum.
- This deployment also includes the previously verified workspace navigation,
  dark appearance, roster claim expiry/validation, analytics links, and
  multiple-company roster regression coverage.

The marketing homepage was reviewed. These corrections do not change advertised
capabilities or the staffing workflow, so no new marketing claims are needed.

## Security scan review

The unsafe stored social URLs flagged by Brakeman were corrected. Five remaining
warnings were individually reviewed, without adding suppression entries:

- Form builder `class_eval`: helper names come from Rails' fixed helper list,
  not request input.
- Two experience-search SQL warnings: interpolated field names are private-call
  symbols or fixed taxonomy constants; search terms are bound parameters.
- Offer mass assignment: `role` is the offered job title, not an authorization
  role. Offers are scoped to the owner's jobs and handled by the offer service.
- Job status CSS: the helper returns fixed literal classes for every branch.

## Operational limits

The free hosted demo still intentionally disables payments, Google sign-in, and
outbound email. Roster invitations use manually shared, expiring claim links.
The free Render service can sleep; scheduled work runs only while it is awake.
The checks here do not verify SMTP deliverability, live Stripe settlement,
provider backups, or disaster recovery. See `production-readiness.md` before a
paid production launch.
